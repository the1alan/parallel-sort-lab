# Parallel Sort Lab

Учебный проект по дисциплине «Алгоритмы и структуры данных», тема «Параллельные алгоритмы сортировки».
Настольное приложение (Python 3 + Tkinter) для экспериментального сравнения последовательной и
параллельной сортировки слиянием со встроенной `sorted()`.

## Цель и задачи

**Цель:** изучить параллельную сортировку слиянием и на реальных измерениях выяснить, когда распараллеливание
даёт выигрыш, а когда нет.

**Задачи:** реализовать Merge Sort и Parallel Merge Sort; провести воспроизводимые измерения на одинаковых
данных; посчитать ускорение и эффективность; построить графики; оформить результаты (CSV, отчёт, презентация).

## Алгоритмы

| Вариант | Файл | Комментарий |
|---|---|---|
| Merge Sort (последовательный) | `algorithms/merge_sort.py` | собственная реализация, O(n log n), память O(n), устойчивая |
| Parallel Merge Sort | `algorithms/parallel_merge_sort.py` | массив делится на p частей, части сортируются в p процессах (`ProcessPoolExecutor`), затем сливаются в главном процессе |
| `sorted()` | встроенная функция Python | **не наша реализация**; высокооптимизированный Timsort на C, служит практическим эталоном |

Параллельная версия: пул создаётся один раз за вызов; при `workers=1`, при размере меньше порога
(`threshold`, по умолчанию 1000) и при пустом/одноэлементном массиве работает последовательный алгоритм.
Ускорение **не гарантировано**: на малых массивах расходы на запуск процессов и передачу данных больше выигрыша.

## Требования и установка (macOS)

* Python 3.11 или новее, Tkinter, Matplotlib.

```bash
cd parallel-sort-lab
python3 --version                      # 3.11+
python3 -m tkinter                     # должно открыться маленькое окно Tk; закройте его
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Если `python3 -m tkinter` пишет `No module named '_tkinter'` (Python из Homebrew), установите Tk для вашей версии Python,
например: `brew install python-tk@3.12` (версию подставьте свою), либо используйте установщик с python.org.

## Запуск

```bash
python3 main.py                        # графический интерфейс
```

В интерфейсе: задайте размеры (через запятую), типы данных, алгоритмы, число процессов, число повторов
и нажмите «Запустить». Строки таблицы появляются по мере измерений, графики строятся по готовым результатам.
«Остановить» прерывает эксперимент между замерами (уже начатая сортировка дорабатывает до конца).
«Повторить эксперимент» запускает последнюю конфигурацию заново; результаты предыдущего запуска заменяются.
Кнопки внизу — «Экспорт в CSV…» и «Сохранить графики (PNG)…» (по умолчанию в папку `results/`).

По умолчанию стоит небольшой демонстрационный сценарий: размеры 10 000 и 100 000, данные `random`,
все три алгоритма, p = 1, 2, 4, 3 повтора. Максимальная матрица автоматически не запускается.

### Запуск без интерфейса

```bash
python3 cli.py --sizes 10000 100000 300000 --types random sorted reversed --workers 1 2 4 --repeats 5 \
    --csv results/run.csv --charts results/charts
```

## Эксперименты и метрики

* Массив генерируется один раз для пары (размер, тип) и **не входит** в измеряемое время; всем алгоритмам
  передаются одни и те же данные (`random` генерируется с фиксированным seed = 42).
* Время — `time.perf_counter()`; для параллельной версии это полное время вызова: запуск пула, передача данных,
  сортировка частей, финальное слияние.
* Для каждого размера/типа/алгоритма — N повторов, в таблице **медиана**.
* Каждый результат сверяется с `sorted(входных_данных)`, также проверяется, что вход не изменён (колонка «Корректно»).
* **Ускорение** `S(p) = T_Merge Sort / T_Parallel(p)`; **эффективность** `E(p) = S(p) / p`.
  Если Parallel Merge Sort выбран, последовательный Merge Sort измеряется всегда — это база для S(p).
  Если метрика неприменима, в таблице и CSV стоит «—» / пустое значение.
* Колонки CSV: `algorithm, size, workers, data_type, repeats, median_time_s, speedup, efficiency, correct`
  (кодировка UTF-8 с BOM, открывается в Excel/Numbers).

## Ограничения и известные особенности

* Реальное ускорение зависит от числа физических ядер. Если p больше числа ядер, процессы конкурируют за них,
  и параллельная версия медленнее. На малых n (порядка 10⁴) накладные расходы обычно перекрывают выигрыш.
* Для p = 1 пул не создаётся, поэтому S(1) ≈ 1; отклонение от 1 — шум измерений.
* Каждый вызов параллельной версии создаёт новый пул (метод запуска `spawn`, как по умолчанию на macOS);
  это честно включается в измеряемое время.
* Финальное слияние последовательное (в главном процессе) — ограничение ускорения по закону Амдала.
* Для достоверных чисел закройте другие тяжёлые программы, подключите ноутбук к питанию, берите ≥ 5 повторов.
* Размер 1 000 000 включайте только если компьютер справляется: Python-реализация Merge Sort на таком массиве
  работает заметно дольше (секунды на замер); максимум в интерфейсе — 5 000 000 (с предупреждением > 1 000 000).
* Остановка эксперимента не прерывает замер, который уже идёт.
* Фактический замер из поставленного комплекта выполнен в Linux-контейнере с 3 логическими CPU; это не Mac команды.
  Результаты зависят от оборудования, версии Python и загрузки системы. Перед защитой рекомендуется повторить
  эксперимент на компьютере команды и при необходимости обновить CSV, графики, отчёт и презентацию.
